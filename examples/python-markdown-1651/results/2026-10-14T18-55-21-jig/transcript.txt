## Root cause

In `markdown/htmlparser.py`, `_HTMLParser.parse_endtag` handled `</` followed by a non-letter (like `` `</` ``) by emitting it as data, but for `</` followed by a letter it delegated to the stdlib `parse_endtag`.

The stdlib returns `-1` when the end tag isn't closed (no `>`, e.g. `</dev/null`; there's no `>` anywhere after it). In `HTMLParser.goahead`, a `-1` return at end-of-input hits the `</` + letter branch, which does `pass` and then sets `i = n` — silently discarding **everything from that point on**. That's why the rest of the sentence and the following paragraph disappeared with no error. Shell redirections like `2</dev/null` and `cat </etc/hosts` trigger exactly this.

## Fix

`markdown/htmlparser.py` — when the stdlib returns `-1`, treat the `</` as literal data and advance (matching the existing behavior for `</` and unterminated start tags), instead of letting `goahead` drop the remainder:

```python
endpos = super().parse_endtag(i)
if endpos == -1:
    self.handle_data(self.rawdata[i:i + 2])
    return i + 2
return endpos
```
